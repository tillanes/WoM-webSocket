WoM WebSocket API

A real-time messaging server built on Socket.IO. Clients connect with a JWT, and every connection belonging to the same user shares one room, so messages and typing updates sync across all of that user's tabs and devices.

Overview

Base URLhttps://wom-websocket.onrender.com
ProtocolSocket.IO v4 (WebSocket with HTTP long-polling fallback)
AuthJWT in the Authorization header, verified with JWT_SECRET
CORSAll origins allowed (*)

HTTP

The only HTTP endpoint is GET /, which serves static files from src/public/ (this page). Everything else goes over Socket.IO.

Connecting

Send the token as a Bearer token in the Authorization header of the handshake. The server verifies it before the connection is accepted. 

const { io } = require('socket.io-client');

const socket = io('https://wom-websocket.onrender.com', {
  extraHeaders: { authorization: `Bearer ${token}` },
});

socket.on('connect', () => console.log('connected', socket.id));
socket.on('connect_error', (err) => console.log(err.message));

Token payload

The server reads these claims from the JWT:

ClaimTypeUsed for
substring / numberUser ID. Decides which room the socket joins (user:<sub>).
usernamestringShown as the sender on messages and typing updates.
expnumber (Unix seconds)Expiry. Used to schedule the auth:error warning.

Connection errors

If the handshake is rejected, the client receives connect_error with one of these messages:

err.messageerr.dataCause
Token expired{ status: 401 }The JWT's exp is in the past. Get a new token and reconnect.
Authorization failednoneMissing header, malformed token, or wrong signature.
Browser clients: browsers cannot set custom headers on a WebSocket connection. extraHeaders only works there with the polling transport. Node clients and Postman work as shown above.

Rooms

On connect, each socket joins the room user:<sub>. All events below are scoped to that room: only connections authenticated as the same user receive them. Two different users do not see each other's messages.

Events

client → servermessage:send

Sends a chat message to the room.

Payloadstring: the message text. Leading and trailing whitespace is trimmed.
ResultThe server emits message:new to everyone in the room, including the sender.
socket.emit('message:send', 'Hello!');

server → clientmessage:new

A new message was posted in the room.

{
  "user": "alice",          // sender's username
  "text": "Hello!",         // trimmed message text
  "sentAt": 1760870400000   // server time, ms since epoch
}
socket.on('message:new', (msg) => {
  console.log(`[${new Date(msg.sentAt).toLocaleTimeString()}] ${msg.user}: ${msg.text}`);
});

client → servertyping:update

Shares what the user is currently typing (a live preview). Emit it on every input change, and with an empty string when the input is cleared or sent.

Payloadstring: the current contents of the input.
ResultThe server emits typing:live to everyone in the room except the sender.
input.addEventListener('input', () => socket.emit('typing:update', input.value));

server → clienttyping:live

Another connection in the room is typing. Key it by id, since one user can have several connections.

{
  "id": "pXf3...",   // socket ID of the typing connection
  "user": "alice",   // username (missing when sent on disconnect)
  "text": "Hel"      // current input; "" means stopped typing
}

When a connection disconnects, the server sends typing:live with { id, text: "" } so other clients can remove its typing indicator.

server → clientauth:error

Sent once, 1 minute before the token expires (or right away if the token has less than a minute left when you connect). 

{
  "status": 401,
  "message": "Token expires in 1 minute"
}

The server does not disconnect the socket when the token expires. The client should get a new token and reconnect with it: 

socket.on('auth:error', async () => {
  const newToken = await refreshToken();   // your auth service
  socket.io.opts.extraHeaders = { authorization: `Bearer ${newToken}` };
  socket.disconnect().connect();
});
